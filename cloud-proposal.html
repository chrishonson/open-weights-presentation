Proposal · open-weights deck

Same model, three venues

Run models from the local benchmark on a rented cloud GPU and through OpenRouter, each in the build that suits that hardware best, and compare speed and quality on the same challenge questions.

Three makers plus one red-team fine-tune. Every venue gets its fastest build, so the weights differ in precision by platform, and the slide says so. The cloud runs happen unattended overnight. Nothing is demoed live.

How it runs

Same questions, same settings

quiz.py --set challenge

29 questions that separate models, temperature 0, thinking off, empty system prompt, 6,144-token cap. Speed comes from one streaming client used on every venue.

MacBook Pro
M1 Max, 64 GB. Ollama 0.40.6 with Apple-optimized nvfp4 builds on the MLX runner. Already scheduled in the local night runner.
Cloud GPU
AWS g6e.xlarge, one NVIDIA L40S (48 GB). vLLM serving FP8 checkpoints, the precision the L40S runs natively. Ollama for the red-team model, which only exists as GGUF.
OpenRouter
Pinned to DeepInfra, no fallbacks, which serves bf16 or fp8. Same OpenAI-compatible client as vLLM.

Why the GPU costs more for the same work

You rent the whole GPU by the hour. OpenRouter sells you a slice of a busy one.

$1.86 per hour divided by the output price. One request at a time, the Mac writes 14 to 66 tokens/sec on these models. The overnight run measures the L40S figure that goes beside these bars.

Sharing is the main reason

Writing each token means reading the model's weights from GPU memory. One user waits on that read. A provider answers dozens of requests in the same read, so one GPU-hour is split across many customers. This run sends one request at a time.

You pay for idle time

Booting, copying the models, loading them, and the gaps between questions are all billed. A provider's GPU is never idle on your behalf.

On-demand list price

On-demand is the highest price for any card. Spot and smaller GPU clouds cost less, which narrows the gap but does not close it without sharing.

The compute per token is about the same. The GPU's utilization is not: a single-user overnight run uses a small fraction of what the card could serve.

Risks

R4Each venue runs a different precision: 4-bit on the Mac, 8-bit on the GPU, 8 or 16-bit on OpenRouter. A score gap mixes the platform with the precision, so the slide labels each row with its build.

R6The challenge set has 29 questions, so one answer moves a score by 3.4 points. Hosted providers are not always deterministic at temperature 0, so OpenRouter runs twice and both results are reported.

R8"Thinking off" is set differently on each server: Ollama's think, vLLM's chat-template switch, and OpenRouter's reasoning setting. A model that thinks on one venue and not another will look slower and score differently, so the client checks every reply for thinking text.

R9All three models are recent architectures. The vLLM version has to support Qwen 3.8, Gemma 4 and Nemotron 3.5, and the first step on the GPU checks that before the night starts.
